# SLOT：复用分解精化后的相邻漏压验证（2026-10-13）

## 1. 目的与固定条件

本批承接 [线性精化与共享诊断验证](slot_ldmos_vm_refinement_shared_diagnostics_2026-10-13.md)，
从其 13.008 mV 诊断接受态出发，独立热启动至 21.04384、30.6、42 mV。
这三个是本批明确指定的目标，后两个采用圆整值，不宣称逐位复刻原生采样序列。
每目标一次尝试，失败停止并保存诊断；无外推、无自动二分、不启动长扫描。

固定 Vg=5 V、漏压原点 0 V；13881 节点、27275 三角形。保留 AverageBox、
定义积分 Fermi、有效带边 SG、完整电离及原材料参数。PARDISO binary64 单线程，
保留全部 ψ，自载流子块消去 2494 条约束，求解维数为 39149。
浓度有限步 β=0.001、电势对数阻尼；载流子正则化与闭合方程替换关闭。

原 Jacobian 方向计算 U；略去输运迁移率对 QF 梯度直接导数的诊断方向用于更新。
每步检查两套 RHS 逐位相同，两套线性系统均须通过原混合、块与约束误差保护。
启用 `linear_factor_refinement_steps=3`，关闭行坐标精化，启用共享与紧凑诊断。
只有未通过线性保护时才尝试复用原分解修正，未放宽阈值。

RHS≤1e-10 或原始归一化更新误差<1 为本诊断停止口径；逆映射、数值有效性及
文件一致性继续检查。行比、闭合、边界和 QF 盒均单列报告。
入口仍返回 `qualified=false`、退出码 1 与 `diagnostic_primary_satisfied`；
本批“接受”专指控制器核对停止原因、保护和文件复读后允许诊断续算，不是生产资格。

每目标最多 25 次更新、软截止 1080 s、硬截止 1200 s；独立复读上限 120 s。
控制器总上限 3600 s，并用剩余预算截短子进程。通过脱离 SSH 的任务执行，
既有 IdVd/BVDS 长任务保持原样。具体远端路径、任务号存于忽略目录中的清单。

## 3. 复核口径与证据

每点使用其配置独立重读最终 HDF5，比较整体残差、SG 漏极电流并复核文件哈希。
复读一致性没有额外要求 RHS 单项达标，保留原 R 或 U 接受语义。
配置对比仅允许漏偏压、输入状态、输出位置及剩余软预算变化；父态链逐点哈希绑定。

导入检查有一项浮点字面值差异：原父态配置漏压为 `0.013007999999999999`，
本批导入探针使用 `0.013008`，相差一个 binary64 ULP。父态文件不变，电流相同，
探针整体残差由原报告 5.410408266e-11 变为 5.333289603e-11，均达标。
因此该导入探针不作为“原配置残差逐位复现”的证据；各新目标的求解与复读使用
同一个偏压字面值，二者直接比较。此现象也提醒：极小绝对残差对边界表示敏感。

控制器、只读状态工具、下载审计脚本与私有远端清单：`build/s13adjacent/`。
完成证据保存在该目录的 `evidence/adjacent_validation/`，包括每点完整迭代记录、
状态、配置、复读与 SHA-256 清单。它们属于记录审计，不是不同初值独立数值复求。

本地下载后逐项验证 70 份文件的 SHA-256；冻结配置及父态链一致性检查通过。
原完整矩阵仍保留在 VM，下载包主要保存状态、JSON、日志及 CSV。
本批没有变更 C++ 实现或物理配置，因此未重复编译或重跑上一批已通过的求解器测试；
执行的是三个新偏压的实际数值验证、三次保存态复读及脚本语法检查。

## 4. 评估与后续边界

**支持在新的、有预算限制的 IdVd 诊断续算中采用本精化选项。** 本批直接证明
它可在保持线性阈值的同时修复首步拒绝，并连续支持 8.04–11.4 mV 的跨度，
不必因该线性质量问题重复减半。只在 21.04384 mV 首步实际触发过精化，
不能把后两点的成功全部归因于精化，也不能声称高偏压一定没有其他失败。

每点主求解仍约八分钟。线性修正改善的是可达性，当前主要成本仍为双系统
装配/求解和载流子、闭合、端口评估。此 runner 未包含后来仅编译过的完整计时
补充，不能把未归属的初始化、保存等时间擅自计为装配。表中的主求解耗时为
外部测得的完整进程时间，复读另列。

后续可从已核对的 42 mV 态建立新的独立批次，保留相同物理、R/U、线性保护、
最多三次精化及失败减半，按原自适应策略有界推进。不能直接覆盖既有长任务。
本批仅覆盖低偏压三点，尚未验证 1 V、60 V、不同初值全场复现或 Sentaurus 定量
一致性；因此结论是“具备继续有界推进的证据”，不是“完整长扫描已验证”。
