## 新增统计与口径

统计仅在开启性能记录时采集，不改变线性求解控制或默认后端。
`linear.factor_statistics` 单独记录新增统计成本，嵌套在 `linear.total` 内。

1. 两后端每次新数值分解记录 L/U 非零元及填充比；相同矩阵仅换 RHS 不重复计数。
2. SparseLU 记录当前编译所选 COLAMD/AMD；UMFPACK 记录 Info 返回的实际策略及排序。
   AUTO 的对称策略是排序/主元策略，不表示把数值非对称矩阵当成对称矩阵求解。
3. UMFPACK 使用库报告的 FLOPS、最大波前条目、内部峰值内存及实际精化步数。
4. SparseLU 未公开 FLOPS 计数器。以保留因子结构计算传统标量 LU 运算量估计：

   `sum_k l_k * (1 + 2*u_k)`，其中 `l_k` 是 L 第 k 列严格下三角条目数，
   `u_k` 是 U 第 k 行严格上三角条目数。含超节点存储填充；不含主元搜索、
   内存管理以及分块内核额外运算。它与 UMFPACK 库计数不是完全相同口径，
   二者均非硬件浮点指令计数，不据此比较 GFLOPS 或精确拆分加速贡献。
5. Windows 在子进程退出前读取 OS 进程生命周期峰值工作集。
   整条曲线报告各求解子进程峰值的最大值，不能相加，也不是父子进程同时占用总量。
   UMFPACK 内部峰值估计与 OS 进程峰值分别列出，SparseLU 未公开内部峰值记为不可用。
6. 汇总按实际分解/观测次数加权，避免等权平均不同点服务的均值。
   完整曲线统计包含点服务内部的 Poisson 等线性调用；不是仅统计漏压主 Newton。
   固定矩阵回放则严格对应冻结的 30,723 阶三变量系统。

## 结论与范围

本轮完成 Windows 等温 D5/D4 全曲线两轮配对，UMFPACK 数值资格通过，
因子填充和分解收益得到量化。D4 在两轮中保留明确端到端收益；D5 的墙钟
波动阻止本轮认领普遍稳定的端到端加速。默认后端保持 SparseLU。

后续性能决策应先在负载可控的环境复核 D5，并比较关闭结构计数时的完整耗时；
排序/主元单变量对照才可进一步拆分收益来源。本轮没有新增 G3、D0 或真实人工
中断续跑专项，不将本次资格转移到这些范围。
