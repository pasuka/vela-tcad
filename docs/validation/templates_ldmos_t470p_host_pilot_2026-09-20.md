时间单位 s。两端使用完全相同的程序、DLL、输入及线程配置。

| umfpack | 195.225 | 170.256 | 12.79% | 180.484 / 168.359 | 349 / 349 |
| strumpack | 349.245 | 228.840 | 34.48% | 267.188 / 227.438 | 349 / 349 |

两端各 5 条曲线、40 个精确点、335 个有效线性点服务线程审计通过；0 次外层回退。
40 对精确状态逐点校验，ψ/fn/fp 最大绝对差 8.881784197001252e-15 V，
低于既有 1e-8 V 门限。各后端跨主机推进目标序列均相同。UMFPACK、STRUMPACK
和 MUMPS 的逐服务 Newton 更新序列相同；SparseLU 为 358→354、SuperLU_MT
为 357→358。未定位这两项微小轨迹差异的具体来源，不能称为逐比特相同求解过程。
原门限不变，不将 4 次或 1 次更新变化从实际总成本中扣除。

## 负载和解释

| 后端 | N150 / T470p 整机平均忙碌率 | N150 / T470p 估计后台 CPU·s | N150 / T470p 求解进程峰值 MiB |
|---|---:|---:|---:|
| umfpack | 49.58% / 13.81% | 206.69 / 19.67 | 245.5 / 244.1 |
| strumpack | 56.51% / 13.50% | 522.27 / 19.80 | 256.7 / 254.9 |
| sparselu | 43.40% / 13.61% | 198.39 / 19.20 | 261.1 / 257.4 |
| mumps | 40.99% / 13.62% | 156.66 / 18.20 | 243.5 / 242.3 |
| superlu_mt | 44.53% / 13.65% | 192.52 / 19.09 | 266.1 / 267.5 |

整机百分比的分母分别为 4/8 个逻辑处理器，不能直接据其比例判断 CPU 快慢。
估计后台 CPU 为采样总忙碌 CPU 减去计入的控制器及点服务 CPU；含口径边界误差，
不是精确进程归因。N150 的后台负载明显较高，因此墙钟优势包含负载差异。
T470p 的计入 CPU 时间也较低，本轮约为 N150 的 85%–96%；但 OS、
CPU 微架构/调度、动态 BLAS 内核及少量迭代差异尚未独立隔离，不作纯 CPU 基准结论。

本轮 T470p 的后端耗时顺序为 UMFPACK、MUMPS、SuperLU_MT、SparseLU、STRUMPACK。
这只是当前单线程 D5 八点样本；不覆盖高压段、D4/IALMob、电热或多线程配置。

## 建议与续接边界

建议将后续独立后端性能比较批次优先安排在 T470p：当前程序可直接运行，
五后端均合格，本轮更快且对日常使用的 N150 干扰更小。
正式迁移时应在 T470p 建立独立冻结目录，先完成双栅压完整曲线资格，
再在该主机内部进行至少三轮交错串行比较。保持同一程序/DLL/输入和单线程，
记录供电、电源方案及后台负载；当前压缩包可复用，无需重新编译。

不得将 N150 已完成的两轮与 T470p 的一轮合并成“三轮同环境计时”。
本次没有恢复旧批次、启动完整长曲线队列、修改生产默认或恢复定时检查。
