- runner 对此失败返回 3，写 `numerical_failure.json`，保留初始 merit、
  20 次 alpha/试探 merit/有限性、耗尽裁剪与 QF 上限触发数量；
  非有限试探 merit 写 null，不能把 NaN 当有限值传递。
- 报告绑定配置原始字节、输入状态与物理资源 SHA256，拒绝覆盖旧失败报告。
- Python 在执行前拒绝陈旧报告，保存输入身份；执行后验证结构、数值、
  下降拒绝条件和前后身份一致，只有此时抛可恢复 `NumericalFailure`。
  exit 3 缺少有效报告、exit 0 缺 CSV 等属于证据故障；一般退出码和 DLL
  错误不降级；子进程超时和总预算保留各自语义。
- 修正器在适配层抛异常时先写失败步骤，再原样传播；不新增 QF 阶段切换。
- schema 说明与对应回归一起更新。

## P1 重放新增的诊断事实

初始冻结权重 merit 为 `13.853289778505763`；20 次回溯均有限且未通过。
alpha=1 时 merit 相对增加约 255.676%，耗尽裁剪 130 个分量、QF 限制 148 个分量。
最后 5 次（alpha 从 `3.0517578125e-5` 到 `1.9073486328125e-6`）
两种裁剪计数均为零，merit 仍相对增加约 `2.0870e-4` 至 `1.2660e-5`。
因此不能把本次 20 次拒绝完全归结为“小步长仍触发裁剪”。
这仍不是方向差分/Jacobian/后向误差验证：密度 log 映射的有限步长效应、
解精度与导数一致性尚未分离，不能据此直接认定物理模型或 Jacobian 错误。
