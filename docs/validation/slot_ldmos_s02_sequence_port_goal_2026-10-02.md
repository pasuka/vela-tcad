### 同一保存态的配对验证

c02 前置行审计恰好全通过，电子最差行比 `7.21485e-4`，因而跳过修正；
其他三次分别仍有 2、2、5 条电子超标行，均走了修正。
直接跨这两种恢复流程做割线，将处理流程变化混入了端口响应。

在 **c02 完全相同的前置 Poisson 保存态和内压**上，补做一次载流子修正及
Poisson 修复，随后重新执行原全部资格与固定目标确认。没有新增耦合提议。
证据 `build/s02port_control/`，补充操作 68.44 s；连同原批及分析等待，
原第二批总墙钟 **930.96 s < 1,200 s**，没有延长原预算。

- 同态配对修正使严格派生外压改变 **−0.047305871625 V**，
  将固定目标残差从 +47.306 mV 降到 **+0.0996495 µV**。
- 电子/空穴最差行比 `1.18110e-6 / 2.05615e-4`，全部有效行通过；完整器件、
  全局闭合、原实际外压及固定目标外压确认分别通过。
- 相对 p03，电流相对差 `4.34248e-10`、内压差 `−1.46549e-14 V`；
  ψ/物理 φn/物理 φp 最大场差 `1.50990e-14 / 1.83462e-11 / 2.08429e-11 V`。

本配对结果支持“恢复流程切换是本轮外压响应跳变的重要来源”。
不能据此宣称所有门槛内状态有唯一电流，也不能把原先 c02 判成不合格：
它通过原资格，只是与指定外压目标不一致。
本批不放宽负载线容差，不改变电流口径，全部端口计算使用严格 SG 电流。

新的 Python 进程复核了 **9 份完整器件证明、9 份实际外压确认、1 份固定目标确认**，
以及源文件、旧账本和证据哈希；`build/s02bvgoal/preflight.json` 记录通过。

第三阶段 `build/s02bvgoal/` 使用冻结 Python 副本和同一诊断 runner：

- 入口 `worker.py`，一次性当前用户 Windows 计划任务 `VelaSlotRepairGoal20261002`；
  已核对实际控制器、监督进程和 runner 活动。
- 从 p03 合格态起，固定执行一次载流子修正及随后 Poisson 修复，
  防止修正开关再次改变端口映射；即使前置行已通过也不跳过该步。
  这是显式的实验恢复策略，未改原设备验收门槛。
- 每步提议 `0.20 R I_parent`，失败从原提议减半到 10%、5%；
  最多三档失败后停止，不无限缩步。实际增长守卫仍为 25%。
- 原始候选相对严格电流偏差另加 **0.5% 工程保护**，超出则回退；
  不以修正后质量替换原始候选质量，不把该工程值当成物理误差界。
- 求解总预算 10,800 s，监督上限 10,920 s，最多 100 个新增点。
  Windows 任务总上限 3 小时 20 分钟，包括最后审计；不自动重启或延长。
- 停止目标：首个完整合格态 `abs(Id)>=1e-7 A/µm` 或物理外压 200,000 V。
  预算/重试耗尽不算达到目标；结束后由新进程对接受账本独立审计，
  跨电流判据时另报线性及对数电流插值。
- 状态只读入口 `status.py` 允许 Windows `FILE_SHARE_DELETE`；
  `run_info.json`、`summary.json`、`exit.json`、`audit.json`、`audit_exit.json`
  区分启动、实际进展、求解退出和审计结果。`completed` 表示本次驱动已退出，
  **是否达成物理目标须另查 `goal_reached` 与 `stop_reason`**。
