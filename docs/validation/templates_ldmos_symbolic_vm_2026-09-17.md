## 公式微基准

以下为同 VM 正/反序的进程 CPU 秒，每个阶段各 1,024,000 次调用。

| 阶段 | 原实现 CPU(s)，正/反序 | 生成或显式实现 CPU(s)，正/反序 | 变化 |
|---|---:|---:|---|
| 低场准备，只求值 | 19.88 / 23.64 | 1.29 / 1.84 | 减少 93.5% / 92.2% |
| 低场准备，值及七偏导 | 21.06 / 22.23 | 3.52 / 3.21 | 减少 83.3% / 85.6% |
| 低场场求值，只求值 | 0.16 / 0.16 | 0.20 / 0.20 | 增加约 25% |
| 低场场求值，值及七偏导 | 0.73 / 0.76 | 0.87 / 0.85 | 增加 19.2% / 11.8% |
| 高场值及三偏导 | 0.84 / 0.82 | 0.28 / 0.29 | 减少 66.7% / 64.6% |

低场准备已经有节点状态缓存。微基准刻意每次重新准备，不能把该阶段的大幅
下降直接外推成器件收益；场求值则在命中准备缓存后仍需执行，生成版本在该
阶段没有收益。还需结合真实命中率和调用分布解释此前 Windows 低场结果。
本轮先完成显式高场完整曲线对照，不在计时矩阵中途修改表达式。

例如此前 Windows V1 的 Vg4 / Vd=0.375 V 冻结种子，在基线和生成低场两侧
均为 640,976 次准备、2,892,064 次命中，命中率 81.86%；56 次装配也相同。
该调用计数只来自旧 V1 代表点，用于说明准备/场求值频次不同，不能将这里
Windows 的计数乘上 Linux 合成样本成本来预测完整曲线节省量。
