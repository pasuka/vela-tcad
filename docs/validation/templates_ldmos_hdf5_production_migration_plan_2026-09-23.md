# HDF5＋HighFive 生产状态格式迁移方案

日期：2026-09-23。状态：代码已统一 HDF5 默认，T470p 功能/恢复及三轮计时
验收通过；C560 Linux Debug 构建及 850/850 CTest 通过，本轮修改整理提交至当前工作分支。进度见
[执行记录](templates_ldmos_hdf5_migration_execution_2026-09-23.md)。下文保留实施前的
缺口说明和阶段合同，最新结果以执行记录为准。

本文落实用户已确定的方向：生产状态文件统一采用 HDF5＋HighFive，直接更新现有
算例，不承担旧状态格式的运行时兼容；性能允许相对 VDS1 增加不超过3%。
本文规定设计、依赖关系和完成条件；执行不更改物理模型或数值门限。
TDR 互操作暂不纳入任务。

## 1. 已有资格与实际缺口

[完整曲线三轮报告](templates_ldmos_hdf5_full_repeats_2026-09-22.md)已经证明：
T470p、Release、UMFPACK/BLAS 单线程、相同保存频率下，D5双栅压共12条完整曲线、
372个精确点和6组联合验收通过；跨格式及跨轮保存字段一致，轨迹和计算计数一致。
HDF5相对VDS1合计墙钟增加0.8695%，各单次配对增加0.2071%～2.2277%。
这是当前实验实现的资格，不能自动转移给扩展schema后的生产实现或D0温度状态。

| 当前实现 | 迁移需补齐的内容 |
|---|---|
| [CMake](../../CMakeLists.txt) 的 `VELA_ENABLE_STATE_FORMATS` 默认关闭，打包多个实验格式 | 独立生产状态依赖；HDF5不再依赖FlatBuffers生成器；实际检测并验证启用状态 |
| [HDF5内核](../../src/io/DDStateFormats.cpp) 使用 `vela.ddstate/1`，保存DD字段 | 明确网格绑定、参考系、模型来源及温度字段；新增合同采用明确的新schema版本 |
| HDF5目前借助VDS1规范字节缓冲复用校验 | 提取共享的内存状态对象和字段校验，避免生产接口依赖旧文件格式 |
| [状态分派](../../src/io/DDSolutionBinary.cpp) 保留CSV/VDS1及按后缀选择格式 | 生产状态入口统一HDF5，错误后缀/错误schema明确报错，不静默回退 |
| [Python适配器](../../scripts/ldmos_binary_adapter.py) 改写CSV路径并挂接实验接口 | 显式、统一的状态读写接口，替换路径猜测和运行时补丁 |
| [电热扫描](../../src/simulation/ElectrothermalSweep.cpp) 仍使用JSON中的状态数组 | 迁移四方程状态、温度和预测历史；保留轻量JSON任务记录 |
| HDF5写出直接截断目标文件 | 临时文件完成并关闭后替换；保存失败不破坏上次有效检查点 |

## 2. 范围：只统一状态持久化，不统一所有文件

| 文件用途 | 处理方式 |
|---|---|
| 初始种子、接受状态、恢复检查点、文件交换中的状态向量 | 统一HDF5；包括分离的QF参考值/增量和已启用的辅助未知量 |
| 自热状态中的晶格温度及用于恢复的电学场 | 纳入同一状态合同，D0单独验证后才认领全流程完成 |
| 电流电压曲线、简要统计表 | 可保留CSV |
| 配置、材料、网格输入及掺杂表 | 保持现有输入格式；不能因扩展名相同而误当旧状态删除 |
| summary、ledger、manifest及小型诊断元数据 | 可保留JSON；大状态数组改为引用HDF5文件，不反复嵌入JSON |
| 原生Sentaurus TDR | 保持现有导入用途，不增加TDR写出或兼容性目标 |
| 已完成实验的历史原始状态 | 不批量转换；保留现存报告、证据和退役说明，不改写旧资格 |

历史JSON/CSV已按用户授权清理，见[清理记录](templates_ldmos_worktree_cleanup_2026-09-22.md)。
“保留历史证据”指保留目前仍存在的证据及清理记录，不表示已删除的逐点状态仍可恢复。
迁移清单必须核实活跃算例实际可用的种子；必要但缺失的输入应按来源重建并重新核验。

## 3. 生产状态合同

### 字段与身份

- 数值采用明确的IEEE 754 binary64磁盘类型及单位；首版无压缩、无有损转换。
  C++与Python按同一合同读写，不能依赖字段遍历顺序或文件扩展名判断内容。
- 保存电势、电子/空穴QF、载流子密度及实际启用的辅助字段；参考电势、QF参考值
  与增量分别保存。禁止先合成再拆分QF而丢失低位信息。
- 四方程状态显式保存 `temperature_K`，记录方程布局和等温/电热模式。
  不为缺失温度的电热检查点静默补300 K；冻结300 K属于显式配置。
- 文件声明schema版本、节点数、字段定义、偏压及输入来源标识。网格指纹覆盖节点
  编号/顺序、坐标、连接关系、区域和单位，不能只比较节点数量。
- 材料、接触、模型及配置的来源指纹在准备阶段计算并复用；不在每次写状态时
  重新读入全部输入。几何大数组无需复制到每个状态文件。
- 不重复存储可重建的线性求解器缓存或LU因子。恢复后重建缓存；本任务不更改
  跨点符号分析复用策略。

### 区分“加载初值”和“恢复扫描”

加载初值允许按显式配置从旧偏压推进到新偏压，但必须校验网格、单位、变量布局和
参考系；模型差异按明确的种子转换规则处理，不能无声接受，也不能将偏压变化一律
视为错误。严格恢复扫描则还需匹配模型、输入、扫描配置和检查点版本。

完整恢复应保存当前算法实际需要的已接受历史状态、目标点位置、步长及恢复阶段。
历史长度由启用的预测策略决定，不能统一假定只需最后两个点。可由JSON ledger引用
HDF5状态文件并保存这些控制信息，但必须验证引用的一致性。
首版保证现有安全检查点的恢复语义，不新增任意Newton迭代中途恢复功能。

### 完整性与保存顺序

1. 写同目录临时HDF5文件，完成必要校验、flush并关闭句柄。
2. 检查替换结果，成功后才更新ledger中的检查点引用；采用版本化状态文件或等效
   事务方案，避免覆盖被旧ledger引用的有效状态。
3. 写失败、磁盘不足或进程中止时，保留上一组完整检查点；启动时能识别孤立临时文件。
4. 限制节点数、字段数、维度和分配大小，检查必需字段、重复定义、类型、单位及
   非有限值；具体数值合法性沿用现有物理接口，不另行放宽门限。

正常进程中断恢复与突然断电的持久化保证分别说明；仅有HDF5 flush不能作为断电
安全已经验证的证据。Windows文件替换与Linux路径均需测试。

## 4. 串行实施与阶段完成条件

| 阶段 | 实施内容 | 完成条件 |
|---|---|---|
| M0 清单与冻结 | 列出活跃算例、种子、恢复入口、测试夹具、散列及现有保存语义；隔离历史目录 | 每个迁移对象有用途、来源、存在性和责任入口；不把曲线CSV列作状态 |
| M1 合同与构建 | 确定新schema、共享状态对象、HDF5/HighFive依赖及Python环境 | 标准构建实际具备状态读写能力；缺依赖明确失败；无需FlatBuffers即可构建HDF5路径 |
| M2 通用等温读写 | 接入C++/Python、预测、参考系转换、审计、原子检查点 | 双向互读及拒绝错误输入通过；保持拆分字段；旧生产格式回退移除 |
| M3 活跃算例迁移 | 一次性转换可用种子，更新路径、manifest和合同测试 | 新种子验证后才替换旧配置并删除被取代输入；所有活跃等温算例可运行 |
| M4 电热完整接入 | 温度、四方程布局、历史状态及严格扫描恢复 | 冻结300 K和低/中/高偏压自热验证通过，D0恢复结果合格 |
| M5 最终回归与计时 | 完成相关长曲线、交错配对和发布包验证 | 数值/恢复/性能条件全部满足后，宣布统一生产格式完成 |

M0～M4可以分提交审查，但未覆盖D0时只能报告“等温入口已迁移”。生产默认切换与
活跃配置更新必须作为一致的改动交付，不能留下默认写HDF5、下游仍按CSV解析的中间版本。

### M1：构建与分发补充

标准配置的状态功能要求HDF5与HighFive实际可用，不能把现有TDR导入开关或
`VELA_ENABLE_STATE_FORMATS=ON`本身当作依赖已满足。状态功能与可选TDR导入应分清。
同步检查CMake预设、Linux/Windows CI、Python回归环境与T470p分发包；Python状态工具
安装匹配的h5py/numpy，Release包带齐实际加载的运行库，并做包外启动测试。
移除HDF5路径对flatc、FlatBuffers生成文件和Python模块的非必要依赖；其他独立用途
先审计再删除。更新配置文档、构建说明和实际启用功能的报告。

### M3：一次性转换补充

转换工具限定用于仓库迁移，不成为生产运行器的旧格式回退。分别记录源文件字节散列、
目标文件字节散列及解码字段摘要；验证的是源解析器得到的数值与目标解码值一致，
不是要求CSV和HDF5文件散列相同，也不是试图恢复CSV写出前已经丢失的精度。
若现有读取器有明确的规范化行为，应记录并保持，不能借迁移改变数学初态。

HDF5两个合法写出文件未必逐字节相同，数值对照应比较规范解码后的字段；文件SHA-256
用于确认具体证据和依赖未改变。所有manifest更新必须来自实际生成文件，不手填旧值。
迁移后检查脚本不再猜测 `.csv` 对应的 `.h5`，配置中使用真实路径。
旧配置的历史报告保持原文，新的活跃配置和验收报告标明迁移版本，避免旧资格误用。

## 5. 验证矩阵和验收口径

| 层级 | 必须验证 |
|---|---|
| 编解码 | C++→Python、Python→C++及各自往返；所有启用字段、QF拆分表示、温度、边界数值；与源解析值一致 |
| 错误输入 | 截断/损坏、未知版本、错误类型/单位、字段缺失、节点同数但顺序或网格不同、异常尺寸；明确拒绝 |
| 文件事务 | 写入/替换失败、ledger提交前中止、临时文件残留；上次有效检查点仍可恢复 |
| 种子与预测 | 相同种子、相同目标序列；参考系转换前后、跨点预测、失败回退；不靠放宽门限消除差异 |
| 完整恢复 | 已接受点暂停后续跑对照不停机运行；自适应步长、目标截短和历史恢复正确；无重复/漏失曲线点 |
| 活跃算例 | 对清单中的普通器件和量子辅助状态执行对应回归；LDMOS复核G3/D5/D4，D0另核温度及热平衡 |
| 构建和集成 | 受影响目标、Python回归和完整CTest；Windows/Linux实际依赖及Release分发包冒烟检查 |
| 性能 | T470p同Release条件、同后端/线程/输入/输出范围，最终HDF5与冻结VDS1对照，三轮双栅压交错串行 |

数值文件转换本身要求解码值一致；最终曲线沿用原电学、热学与局部场验收门限。
纯格式切换若导致Newton轨迹或更新数变化，应先定位初态、参考系或恢复差异，
不能仅以最终电流接近判定无影响。D0的300 K冻结极限、完整曲线与温度恢复必须
补验，不能继承本轮等温D5的资格。

性能使用已批准口径：三轮双栅压配对合计端到端墙钟增幅≤3%，同时公开分栅压、
分轮增幅、保存次数及总文件量。旧VDS1程序只作为隔离的验证基准保留，不能重新
成为生产选项；需确认其物理/求解实现与候选一致，若不同则先建立可比基准。
最终schema、事务写入或转换实现改变成本后应重新配对，当前0.8695%不作为新实现的实测值。
计时不必再遍历其他格式或五个线性后端；本任务聚焦状态格式。

首版不同时开启压缩、减少保存点、内存种子传递或新外推策略，避免把不同变化的收益
合并。D0扩展也需记录耗时与文件量，但D5对VDS1的计时资格不能代替D0的性能证明。
