# SLOT 候选电流偏差与重复验证成本分析（2026-09-30）

## 结论

本轮仅分析既有四组10/12.5 mV短批，未启动求解器、修改物理配置或验收规则。

1. 候选电流系统性偏低约0.373%～0.576%。固定内压严格重闭合时，电子总
   接触通量变化的99.99691%～99.99718%对应原有守恒失配的消除；净积分源
   变化只占其余约0.003%。这把本批主要差异定位在候选输运状态尚未充分闭合，
   而非重新出现了同量级的源项幅值变化。该分解针对电子总接触通量，不是
   把总通量直接等同于单个漏极电流。
2. 找到可研究复用的完整验证：质量修正辅助函数的最终验证及其后的额外严格
   验证均执行0次Newton更新，得到逐字段相同的状态、相同IV行及逐字节相同
   的逐行项文件。后一轮求解与行探针约8.9秒。
3. 仅去掉这一轮仍不足以证明按需修正值得常开。按本批固定路径作理想化扣时，
   10 mV开启组仍比关闭组慢约18.4%；这不是实际优化后的测量值。
4. 更普遍的重复开销在Python侧：每步反复验证历史状态，重复构造网格标识并
   解析同一份审计CSV。应保留内容哈希与资格检查，研究绑定内容哈希的解析
   结果复用，而不是删掉安全检查或放宽质量线。

## 证据范围与方法

- 输入为 `build/s30qualitybatch/` 的四条三点路径、两个独立控制及冻结驱动。
  12条候选记录存在重复路径，不是12个统计独立样本。
- 使用相同原父态、原点36 V、300 K、R=1e12 Ω·µm、13,881节点和27,275单元。
  物理配置仍是IALMob、自洽QF梯度雪崩、外心体积和原生输运耦合受控配置。
  候选配置显式使用 `direct_bordered_qr`；严格路径沿用既有Release程序及后端。
- 最终门槛：abstol=1e-9、reltol=1e-8、全部有效行比1e-3、全局闭合0.01、
  负载线1e-6 V。增步质量线0.5%及行比0.0009没有改变。
- `build/s30candidate_cost_analysis/analyze.py` 验证原清单、各点/候选/确认绑定，
  检查1,035个输入文件的哈希；比较HDF5解码字段而非只比较容器文件字节。
  QF变化按reference/increment分别作差；密度字段单位为m⁻³。
- 不重跑原137项回归。本轮是只读数值与代码分析；新分析脚本已实际运行，
  含平衡恒等式、负载线分解和状态比较检查。既有HDF5版本警告保留。

## 候选偏差的量化定位

令候选为c，固定内压严格态为s。电子总接触通量F、净积分源S和失配m使用
冻结守恒探针/严格IV的同一装配口径，满足：

\[
m=F-S,\qquad F_s-F_c=(S_s-S_c)+(m_s-m_c).
\]

脚本逐点验证这个带符号恒等式。不能把这里的净产生复合源直接改称“总雪崩源”，
也不能把装配通量数值直接标为A/µm。

| 代表点 | 提议外压步 / mV | 候选电流/严格电流−1 | 候选电子闭合比 | 净积分源相对变化 | 消除失配占电子通量变化 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 10 mV关闭，首点 | 10 | −0.423628% | 0.423679% | +1.19565e-7 | 99.997178% |
| 12.5 mV关闭，首点 | 12.5 | −0.555001% | 0.555121% | +1.59396e-7 | 99.997129% |
| 12.5 mV关闭，第三点 | 9.886 | −0.575922% | 0.576075% | +1.78010e-7 | 99.996910% |

全部记录中，候选电流偏差绝对值与电子闭合比最大相差0.000154个百分点。
二者高度对应，但不是通用恒等式；漏极和全部接触的口径必须保持区分。

严格重闭合前的多晶硅恢复没有改变任何Si节点的ψ、n、p或分裂QF字段。
随后严格重闭合保持内压完全相同，Si电势最大改变约3.31e-10～5.16e-10 V，
净积分源相对改变约1.15e-7～1.78e-7，却将候选电流修正约0.4%～0.6%。
这支持“小幅状态修正消除漏电流尺度上的守恒误差”。多晶硅恢复可能经耦合
影响后续求解；没有关闭恢复的单因素对照，不能据此排除其间接影响。

严格重闭合需要1～3次Newton更新，均有实际更新；它不是可删除的零更新复验。
其后的按需行修正则是在已经通过最终资格的状态上改善局部质量：10 mV首点
电流相对变化仅约3.50e-8，不能将这项收益混同于前面的0.4236%候选电流修正。

### 外压迁移不是未闭合的电路误差

逐点检查完整关系：

\[
U_s-U_{\rm proposal}=(V_s-V_c)+R(I_s-I_c)+r_c,
\qquad r_c=V_c+RI_c-U_{\rm proposal}.
\]

本批V_s−V_c=0，候选电路残差最大1.564e-9 V，而严格外压迁移为
1.406～2.257 mV。故该迁移主要来自严格电流改变后的电阻压降，不是内压错配，
也不是1 µV电路容差过松。已匹配实际外压的端口反馈与候选质量检查应继续分开。

### 为什么耦合候选还能显示“收敛”

原候选配置启用 `zero_converged_residual=true`，器件方程容差及其上限均为
1e-8；耦合日志最终方程范数约2.45e-10～2.61e-10，电路残差也达标。
当前 `CoupledLoadLine.h` 的停止条件是器件方程范数和电路残差；冻结全局闭合
及严格局部行资格由外层分别检查。标量范数达标不蕴含所有载流子相对平衡误差
已小于0.5%的增长质量线。

置零策略允许在线性化时省略已达器件容差的右端项，因此“残留小的器件误差、
继续修正电路”与本批证据相容。但本批没有保存逐步置零标志及完整耦合trace，
不能声称已证明每一步置零，或把全部偏差归因于该开关；也没有发现新的Jacobian
错误证据。两个候选迭代的统计不能代替方向导数审计。

同父态10→12.5 mV两点的候选偏差比约1.31，对应两点经验指数约1.21。
只有两个跨度，不能据此证明渐近一阶/二阶，也不能外推高电流区的安全步长。

## 重复验证及实际成本

### 可优先整理的修正验证链

当前质量修正调用链为：一次carrier块 → 块后行审计 → 辅助函数完整验证 →
最终行审计 → `backend.solve(same_bias=True)`再次完整验证 → 再次行审计。

本批唯一触发的修正中：

| 阶段 | 计时 / s | 数据来源 |
| --- | ---: | --- |
| carrier块 | 5.25 | 保存的execute计时 |
| 块后行探针 | 3.25 | 保存的execute计时 |
| 首次完整验证 | 5.80 | 保存的execute计时 |
| 首次最终行探针 | 3.12 | 保存的execute计时 |
| 第二次完整验证 | 5.71（含适配器文件时间区间5.78） | 运行日志/文件时间 |
| 第二次最终行探针 | 3.16 | 保存的execute计时 |
| 整段质量修正 | 30.11 | 驱动单调时钟 |

两次完整验证都执行0次更新，10个解码状态字段全部相等、IV行无差异、逐行项
CSV逐字节相等。配置仍有输出路径、输入状态路径及迭代预算24/40的差别，
元数据source_config_sha256也不同；不能称为两个完整文件及配置完全相同。
两次都是原物理与原最终门槛，当前零更新结果对预算不敏感。

可研究把辅助函数已验证结果通过统一接口转成绑定完整证据的point，而不是再
求解一次。`SolverBackend.solve` 的普通失败恢复分支已有“复用辅助函数最终
行探针并建立qualification/lineage”的先例。需先统一配置契约、预算和谱系，
保留原有效行、闭合、内压、runner/config/state哈希检查及最终电路确认。

仅按观察到的第二轮约8.93秒作乐观扣时，10 mV开启组由176.24降为167.31秒，
推进效率仍比关闭组低约18.4%。要在原三步路径上打平，需省约39.74秒，
大于整个30.11秒修正段。以上是固定路径反事实算术，不是优化已验证收益。

### 常规点并非只有Newton求解耗时

下表来自12条记录的运行日志/保存计时；范围中含重复数值路径。

| 阶段 | 每点耗时范围 / s | 可否直接删除 |
| --- | ---: | --- |
| 耦合候选进程 | 15.21～16.92 | 否，提供候选 |
| 候选冻结守恒探针 | 2.15～2.74 | 否，不能用占位零字段代替 |
| 固定内压严格求解 | 9.54～18.19 | 否，本批均实际更新 |
| 严格态全部行探针 | 3.06～3.51 | 否，保留最终证据 |
| 电路确认进程 | 2.67～3.20 | 否，确认状态不变及负载线 |
| 其余Python/文件/审计工作估计 | 11.22～13.33 | 需分解，不能全部视为浪费 |

最后一行按尝试总计时减去不重叠的进程/探针/修正段估计，部分进程范围用
配置到stdout文件时间辅助界定，不能当成精确Python CPU耗时。驱动在每次
attempt计时开始前还会检查输入和当前父态；这些属于此前报告完整分支墙钟
成本，不应遗漏或误加到某个求解器上。

只读`cProfile`采样（禁用所有求解入口）对关闭/开启组各一份首点调用
`validate`、`validate_confirmation`和`growth_metrics`：

- 单次完整point复核约1.55～1.57秒；其内部会再次解析全部行、检查状态。
- 单次确认复核约0.60～0.66秒；两份状态digest都会重算网格标识。
- 六次状态读取中的网格identity累计约1.80秒；两次逐行审计累计约1.54秒。
- 108次SHA-256累计约0.20秒；文件哈希不是此采样的主要瓶颈。
- 驱动每步会复核最多六个端口历史样本；同一父态还可能经过其他调用复核。

这些是带采样器开销的诊断时间，不是可直接承诺的生产节省量。
优先级应是复用已绑定的网格身份、解码状态digest和解析后的全行审计结果，
而不是首先删哈希或无条件缓存`qualified=true`。

## 建议的后续任务

1. **先统一验证结果复用接口。** 保留证据内容哈希重验，以state、terms、IV、
   config、runner、网格、全部物理输入、参考原点及门槛身份作为缓存/复用键。仅复用不可变的
   已解析结果；恢复运行、配置变更和任何绑定变化必须失效。加入改文件后必拒绝
   的回归，避免用文件名/mtime或布尔标志代替资格。
2. **复用修正器已完成的最后验证。** 提取普通恢复路径已有的绑定/谱系逻辑，
   让质量修正复用同一接口；保留严格状态的数值资格及电路确认。先以本批证据
   重放并验证结果等价，再做极小同父态成本对照。保持默认关闭。
3. **随后做一个候选校正机制对照。** 同父态、同提议比较当前策略与最多一次
   保留原器件右端项的候选校正，原门槛和严格重闭合不变。若再次出现停滞，
   保留明确回退。必须同时记录候选电子失配、raw/strict电流差、实际外压、
   严格Newton成本；不能用校正后的电流覆盖原候选误差来“通过”质量线。

本轮不支持直接扩大步长、关闭候选守恒检查、放宽0.5%质量线或进行全程序
扩展精度改造。是否值得重构候选算法，应在去重后的完整成本与受控对照基础上决定。
