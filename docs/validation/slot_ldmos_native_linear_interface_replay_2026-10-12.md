# SLOT 原生系统通过 Vela 正式线性接口重放

2026 年 10 月 12 日。工作点 Vg=5 V、Vd=0.005 V，300 K；SLOT 网格
13,881 节点、27,275 三角形。使用已导出的 Sentaurus float64 第 0 次系统，
直接调用当前 Vela `LinearSolver::solve(A,b)`，分别选择 PARDISO 和 UMFPACK。

**两个正式后端都复现了原生线性方向。** 方向相对原生 SOL 的块 L2 差约为
1e-12 至 1e-13。单线程下，正式接口与绕过 Vela 的同库 C API 调用结果逐位相同，
未发现接口引入的额外方向差。此结论只适用于本冻结系统，不替代完整 Newton 验证。

## 输入和接口边界

- 原生输入：`build/s10native64/native/double64/matrices/snapshot_0.npz` 和
  `vectors_0.npz`；分别对应 SHA-256
  `401002595d241393a731da735ba6af2c354ed212a615699f7939940ea7654312` 和
  `e6d7d5824131f1633d9e18e1a0eea512a0f8d371b5da4b2a7646404c17898175`。
- 系统 39,149 × 39,149，608,096 个非零元。保持原生变量顺序：13,881 个电势、
  12,634 个电子浓度、12,634 个空穴浓度。求解 `A x = RHS1`，不使用 RHS2。
- 保留原生缩放和边界行，不转为 QF，不重新装配，不增加正则化、闭合替换、
  外部均衡或额外消元。库内部的排序、缩放与精化保留各后端设置。
- Python 只准备 CSC 二进制输入和核对结果。C++ 诊断入口链接通过
  `windows-ucrt64-release` 重新构建的 **当前 `libvela_core.a`**，
  没有复制求解实现，也没有通过 Python API 替代正式接口。
- API 读入并求解后回写全部 CSC 索引、系数和 RHS，与输入二进制文件逐位一致。
  新输入还与此前原生重放的矩阵、RHS 逐元素一致。

诊断入口为 `build/s12native_interface/replay.cpp`，正式实现为
`src/solver/LinearSolver.cpp` 与 `src/solver/MklPardisoBackend.cpp`。
编译命令、静态库、源码和动态库哈希保存于本批证据目录。

PARDISO 使用本机 oneMKL 2026.1、LP64、实非对称 mtype=11、METIS、匹配与缩放、
两次精化；1/4 线程两臂均实际精化两次，扰动主元数为零。
UMFPACK 使用 UCRT64 `libumfpack.dll`，实际排序编号 1、策略编号 3，精化一次；
OpenBLAS 线程环境设为 1。未采用 `*_eliminated` 后端，因为本任务要求原样保留
原生系统。正式接口仅允许 1、2、4 线程；最初 5 线程调用在求解前被参数检查拒绝，
记录保留在 `runs_attempt1.json`，随后改为 4 线程补充臂。

## 与原生 SOL 的方向比较

相对块 L2 差定义为 `||x_local-x_native||₂ / ||x_native||₂`。
电势最大差按原生电势尺度 0.025851995266484913 V 换算；浓度方向保持原生归一化单位。

| 正式后端 | 电势方向相对差 | 电子浓度方向相对差 | 空穴浓度方向相对差 | 最大电势方向差 |
|---|---:|---:|---:|---:|
| PARDISO 1 线程 | 2.162e-12 | 3.063e-13 | 2.828e-13 | 1.393e-14 V |
| PARDISO 4 线程 | 3.173e-12 | 4.509e-13 | 4.122e-13 | 2.002e-14 V |
| UMFPACK | 3.467e-12 | 4.860e-13 | 4.467e-13 | 2.165e-14 V |

三臂最大绝对方向差所在节点均为：电势 5944、电子浓度 10515、空穴浓度 13291。
这里比较的是**线性增量**，不是最终电势或浓度误差。

重点节点的空穴浓度方向如下，单位为原生归一化浓度：

| 节点 | 原生 SOL | PARDISO 1 线程 | UMFPACK |
|---|---:|---:|---:|
| 7518 | -2.482949910605050e-5 | -2.482949910604980e-5 | -2.482949910605013e-5 |
| 10280 | -2.275290605165280e-2 | -2.275290605165390e-2 | -2.275290605165405e-2 |
| 10438 | -9.488950735034130e-5 | -9.488950735034424e-5 | -9.488950735034490e-5 |
| 10849 | 672.351836017885 | 672.351836005446 | 672.351835995886 |

这些节点方向符号一致。不能将它们与先前 Vela 装配的 QF 系统中的方向直接比较。

## 独立残差与接口核对

使用独立 Boost 113 位程序对原始导出矩阵和 binary64 方向累加。
分量后向误差定义为 `|(Ax-b)i| / (Σj|Aij*xj|+|bi|)`。

| 方向 | 相对 L2 残差 | 自由行最大分量后向误差 | 齐次约束最大方向泄漏 |
|---|---:|---:|---:|
| PARDISO 1 线程 | 3.430e-15 | 5.019e-8 | 9.861e-31 |
| PARDISO 4 线程 | 3.800e-15 | 1.413e-8 | 1.479e-30 |
| UMFPACK | 2.528e-15 | 2.139e-16 | 0 |

本系统有 126 条数值上仅含非零对角元的约束行。PARDISO 在这些齐次行的泄漏极小，
但严格分量后向误差会因此等于 1；它与绝对泄漏同时报告，不把这个比值单独当失败。
PARDISO 单线程最差自由行对应节点 13653 电子行，绝对缺陷约 1.26e-22、
分母 2.50e-15；4 线程对应节点 6257 空穴行，绝对缺陷约 1.32e-18、分母 9.32e-11。
UMFPACK 最差行对应节点 10874 电势行。

正式接口与本批独立同库 C API 调用比较：

- PARDISO 单线程、UMFPACK：所有 39,149 个方向分量逐位相同。
- PARDISO 4 线程：整体相对 L2 差 1.149e-18，最大内部单位差 2.328e-10；
  不宣称多线程调用逐位复现，也不把这项微小差异归因为接口错误。
- 各正式接口重复使用相同矩阵和 RHS 的缓存求解，方向均逐位相同。
- 非对称已知解自检全部通过，最大误差不超过 4.441e-16。

因此，本次没有发现正式接口的矩阵转置、RHS 符号、索引转换或缓存引入额外数值
偏差的证据。UMFPACK 在此系统上的后向误差很小，与上一批另一个 Vela 冻结系统的
精化异常并不矛盾；后端表现应按具体矩阵判断。

## 结论与适用范围

原生文件仅以 15 位有效十进制数字保存非零量，原生 SOL 不是这些舍入输入的精确解；
Sentaurus 内部 PARDISO 的库版本和全部参数也未被证明等同本机 oneMKL。
因此结论是数值上非常接近，而非与原生内存求解逐位相同。

本批未改生产源码、物理模型或验收门槛，未启动远端求解或连续 Newton，新增合格
偏压点为零。Release 核心库构建、三臂正式接口重放、同库独立调用、113 位残差核对、
全部分量导出、已知解与缓存检查、输入哈希检查均完成；未因诊断文档运行全量 CTest。

证据目录：`build/s12native_interface/`。主要文件为 `inputs.json`、`build_command.json`、
`verification.json`、`comparison.json`、`all_components.csv`、各臂 `*_quad.json` 和
`*_performance.json`；可复核入口为 `run.py`、`analyze.py`、`replay.cpp`。

后续若要解释完整 Newton 路径，应继续保持坐标和更新规则一致，在每次重新装配后
核对方向与真实试探残差；本次结果不支持把此前非线性差异笼统归因于正式线性接口。
