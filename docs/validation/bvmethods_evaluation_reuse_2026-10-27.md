# BVMethods：T470p／C560 同态求值复用优化

日期：2026-10-27。承接[gprof 热点定位](bvmethods_gprof_hotspots_2026-10-27.md)。
三项优化已实现，并在 T470p 和 C560 完成普通 Release 配对验证。
机器可读[证据摘要](bvmethods_evaluation_reuse_2026-10-27.json)包含所有分项、重复计时、
场数据比较和矩阵文件哈希。现有 VM 完整扫描使用原冻结程序，未被本轮替换或重启。

## 实现与启用范围

1. **同一候选的完整诊断复用。**
   自动恢复控制器检查过的候选携带原诊断对象；若该候选被应用，最终验收直接读取
   同一个对象。被拒绝的完整候选不污染后续近似候选。所有方程、KCL、载流子行、
   全局闭合及高精度账本仍执行原判据。
2. **同态物理／源项及端口复用。**
   `BvMethodsCoupledRuntime` 为同一 assembler 保留最近状态的物理 Evaluation 和
   输运结果，按完整 packed state 的字节精确匹配；有、无 Jacobian 分开存储。
   参考场的位模式变化会清空条目，非零参考场仍拒绝。
   缓存不存储边界替换后的最终 RHS 或矩阵，边界替换、约束掩码与账本标志每次重算。
   同一 NewtonSolver 创建的端口 functional 可通过弱引用共享一个 assembler，
   各端口保留各自的电流权重和单位缩放。
3. **参数导数减少重复装配。**
   对经典 BVMethods、零参考、无 thermionic 且两侧约束节点集合相同的情况，
   先验证一次完整基态 RHS 有限，然后只更新 ±h 的 Dirichlet 行。
   使用原 `x-value` 表达式相减，h 不变，保留原差分舍入；没有直接用解析常数替换。
   条件不适用或基态无效时继续使用原两次完整 RHS 差分。每次参数导数仍保留
   完整有限性检查，未将无效人口变成有效方向。

物理缓存为单 owner、顺序使用的显式选项；网格、掺杂、材料和构成参数在 assembler
生命周期内必须冻结。修改这些输入需重建 assembler，不能将条目跨实例或跨模型复用。
缓存是有界的最近状态条目，不随扫描点数增长。原全局默认值、PN2D 模板及 CMD 默认
流程保持原值。诊断驱动在 manifest 中显式启用：

```json
{
  "evaluation_optimization": {
    "candidate_diagnostics": true,
    "physical_reuse": true,
    "shared_ports": true,
    "boundary_parameter": true
  }
}
```

这些选项默认全部关闭。核心 C++ 的 `diagnosticBvMethodsEvaluationReuse`、
`diagnosticBvMethodsSharedPorts` 及 `makeArclengthSystem` 的可选边界导数参数
由该诊断入口设置，没有新增全局 JSON 默认行为。

## 配对条件

两机分别在新的独立源目录构建 Release／O3，gprof 和 LTO 关闭；MKL PARDISO、
单线性／BLAS 线程及 sequential threading layer，与各自主机的前轮测量一致。
T470p 使用 UCRT64 GCC 16.2，C560 使用 Linux GCC 15.2。
每机校验 245 个文件，覆盖 243 个生产源文件及诊断、测试修改；运行后再次校验通过。

沿用 300 K、2600 节点／5020 Tri3、2152 Si 节点、7801 维边框系统，R=1e7 Ω·μm。
Joyce–Dixon／OldSlotboom、总杂质迁移率、SRH、自洽 GradQF VanOverstraeten AV，
BTBT 关闭。冷 Poisson 起步，自动导数恢复、割线外推、report_only 预测内压设置不变。
40 次正确器预算、τ=0.99 正人口保护、0.1 V 正确器内压限制、原方程／负载线／KCL 门
和 RMS<1 停止门均保持。守恒 report／enforce 选择没有变化。

测量窗口为零偏加首五个非零接受点。将外层尝试预算设为 6 后正常按预设窗口退出，
退出码 3 表示外层预算截止，不登记为完整 BV 收敛或数值发散。
每组均为 7 次冷 Poisson 更新、16 次联立更新，五个非零点次数为 4、3、3、3、3。

每机执行八组：两组带矩阵导出的正确性控制，以及无矩阵导出的全关、仅候选复用、
再加物理与端口复用、全开、全开重复、全关重复。矩阵导出组不进入性能均值。
两个正式配对采用前后顺序反转的全关／全开样本，各取两次平均。

## Release 性能结果

| 主机 | 全关两次，s | 全开两次，s | 均值变化，s | 加速 | 墙钟减少 |
|---|---|---|---|---:|---:|
| T470p | 61.7306、61.2326 | 34.6938、34.8968 | 61.4816 → 34.7953 | 1.767× | 43.41% |
| C560 | 129.5698、129.2033 | 56.4975、57.7945 | 129.3865 → 57.1460 | 2.264× | 55.83% |

分项控制如下，各分项仅一次计时，不能与重复均值混用来证明每个小增量的显著性：

| 显式优化级别 | T470p，s | C560，s |
|---|---:|---:|
| 全关，第一轮 | 61.7306 | 129.5698 |
| 仅候选诊断复用 | 49.9979 | 101.0160 |
| 再加物理和端口复用 | 35.3437 | 57.3204 |
| 再加边界参数导数，全开第一轮 | 34.6938 | 56.4975 |

主要收益来自减少重复检查和物理求值。边界导数路径本身确有阶段耗时下降，
但全墙钟的额外贡献较小，本轮重复数不足以单独量化该项的稳定收益。
两机的 CPU、操作系统、编译器和数学库不同，只比较各自主机的开关配对，
不将跨主机差异全部归因于硬件，也不换算 Sentaurus 加速比。

## 数值一致性与检查

- 每机 24 项相关 CTest 和 152 项 NewtonSolver 默认用例通过，均为 0 失败、0 跳过。
- 八组全部接受点、16 次更新的完整 attempt 记录，包括原始 RMS、各诊断、候选方向
  幅值、线性后向误差、α、切换原因和模型下降比，逐项保留所有数值位模式。
- 每机 48 个接受态 HDF5（八组各六点）的 ψ／fn／fp／n／p，与全关组逐节点逐位相同。
  T470p 的 Python HDF5 DLL 环境未修改；两机状态均回传后使用本机 HDF5 分析环境核验。
- 正确性控制在五点各自首轮导出完整边框矩阵、QF／人口列矩阵、坐标变换、原始方向
  和 RHS／参数导数，共 30 个 CSV 文件；每机的优化前后 SHA256 全部相同。
  这是 Vela 开关配对，不是新增 Sentaurus 算子一致性结论。
- 新 C++ 用例覆盖改变边界后重复求值、1e-13／单 ULP 状态扰动、平衡态、参考场符号位、
  无效人口及恢复、共享端口导数，以及边界路径相对完整差分的逐位一致性。

参数与方向未改变，因而本窗口的更新次数没有减少。低偏全局闭合超线报告也保持原值；
更快求值不能解释为该守恒报告或完整 BV 收敛问题已解决。

## 成本变化及剩余范围

下表来自第一组无矩阵导出的普通 Release；包含式 timer 的父项、子项不可相加。

| 阶段 | 调用次数，全关→全开 | T470p 时间，s | C560 时间，s |
|---|---|---|---|
| 状态检查 | 36 → 22 | 28.5689 → 6.3234 | 72.2147 → 10.9500 |
| 驱动完整 RHS | 68 → 38 | 6.6017 → 2.0862 | 17.0290 → 4.7269 |
| 端口值 API | 248 → 148 | 7.4040 → 0.4821 | 23.2273 → 1.5123 |
| 参数导数 | 16 → 16 | 2.1911 → 0.3802 | 5.0845 → 0.4629 |
| 人口列高精度缺陷 | 16 → 16 | 2.9859 → 2.9724 | 3.8138 → 3.7432 |
| QF 高精度缺陷 | 16 → 16 | 3.0740 → 3.0079 | 3.8314 → 3.8354 |
| 联立 PARDISO | 16 → 16 | 0.9968 → 0.9880 | 1.4919 → 1.4984 |

端口 API 次数包含缓存命中，不等于物理输运实际重算次数。高精度缺陷检查的次数与
精度保持，收益没有来自删门或降精度。旧基矩阵中多余载流子装配、更多跨服务融合
和完整 BV 失败尝试仍有后续定位空间，本轮未修改这些路径。

这是严格同点、有限窗口的普通 Release 性能结果，不外推为完整 BV 的总加速比，
也不单凭缓存通过认领更大的物理模型／状态坐标适用范围。
原始矩阵、源快照、八组输出留在两机；本地校验归档和私有回执保存于 ignored 的
`build-release/bvmethods_optimization_20261027/`。本轮尚未提交本地分支。
