# BVMethods bootstrap保护后模型复核与显式历史验证（2026-11-01）

## 实现与验证范围

依据[2343 V事件审计](bvmethods_direction_projection_audit_2026-11-01.md)，增加显式C++验证控制`CoupledLoadLineConfig::bootstrapModelGuardEnabled`，默认false。本轮用户授权验证该控制及full模式继承；没有改变JSON/CMD默认、统计/迁移率/AV公式、真实RHS、人口保护或原停止门，没有启动新完整BV。

在automatic/full_step下，保护后的bootstrap候选应用前，保持当前状态、目标外压和真实RHS，按所选近似矩阵预测完整设备/电路残差。对实际写回步（含下限/局部保护及舍入）进行100位累加，计算固定设备1e-8和负载线1e-6 V尺度下的L2型诊断merit；它不是新的非线性停止范数。

预测下降未超过64个机器epsilon的相对噪声尺度、且候选未满足原物理残差门时，候选不应用，更新报告清空，模式原因记为`bootstrap_model_non_decrease_restore`，在同态重试完整Jacobian。模型求值异常也请求有界完整复核。完整方向仍走原线性双门、实际人口保护、原完整候选恢复和停止门。

该路径与既有bootstrap线性失败恢复共享一次未更新状态探测额度；实际应用一步后才重置。新模型复核保留同一逻辑Newton轮次，避免消耗额外实际更新预算；trace分别记录被拒绝的bootstrap候选和随后完整尝试。候选RHS已满足原物理门时，不因近零预测下降额外否决，但原RMS及其他停止条件继续生效。

本控制只针对预测无可靠下降；不是已覆盖所有“预测下降但实际增长”的bootstrap候选。完整候选原恢复规则未改，不构成全局收敛保证。

`CoupledLoadLineNewton::solve`另接受显式调用方历史，结果返回独立复制的`derivativeHistory`。普通调用仍每目标重置；只有数值契约相容、接受态的历史才能由调用方携带。失败尝试不得覆盖最后接受历史。当前标准DCSweep未自动继承，实验将“保护后模型复核”和“跨目标历史”分组。

## 结论与适用边界

本次局部验证支持修复：保护后近似模型预测恶化时，在状态未推进前复核完整Jacobian，可避免已捕获2343 V事件，并通过原失败附近的实际暖窗口。显式携带真实返回的Trial/Full历史也已独立通过三目标控制，可减少该窗口中重复进入bootstrap的复核，但标准DCSweep仍未启用历史继承。

这是默认关闭的C++实验控制与独立CLI验证入口。本轮未启动新完整BV、未提交修改，不能宣称全程BV通过、所有困难态或Sentaurus逐轮一致性已闭合。实际暖窗口仍产生33个接受点；本轮没有同主机全程性能对照，不能据此宣称计算效率问题已解决。后续若推进生产入口，应显式接入配置、保留接受/回滚历史契约，再独立验证完整BV。
