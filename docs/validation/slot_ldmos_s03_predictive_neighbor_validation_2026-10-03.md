# SLOT 预测邻行选取与三个相邻点验证

2026 年 10 月 3 日。本批将此前依靠节点编号的单点诊断推广为有界预测选行，
并从合格父态完成三个新的连续点。**三点均首次提议通过原完整器件、全部有效行、
全局闭合、文件绑定及实际外压确认；原行比门槛 0.001 未变。**
最新电流为 `1.111940628900075e-9 A/µm`，仍未达到 `1e-7 A/µm` 击穿判据。
试验已按三点上限结束，没有启动长扫描或定时监测。

## 选行规则和校准中的失败

[局部修正模块](../../scripts/slot_local_row_repair.py) 增加默认关闭的
`--predict-boundary` 选项，需同时显式开启 `--enable-neighbor-repair`：

1. 沿用原规则选入全部超标行及相连的近门槛行，计算局部有限差分方向。
2. 对修正范围外的同载流子一环邻行计算 `r_pred = r + J_all,patch·delta`，
   用当前 scale 预测行比。达到 `0.5*eps_row` 的邻行按预测影响排序纳入，
   总自由度不得超过八个；未纳入的候选仍写入诊断记录。
3. 缓存已有差分列，只为新增自由度增加探针，重新计算扩大范围后的方向。
4. **每次局部修正只在首轮进行预测扩展**；后续轮次使用原选行规则。
   每轮全部有效行重新评估实际行比，按原阻尼和全局条件选取试探。

`0.5*eps_row` 是选行工程策略，不是新验收门槛；预测使用修正前 scale，
实际验收重算 scale。同载流子邻域之外的其他行仍在全有效行检查中，不能被忽略。
最多三轮、每轮八个自由度、QF 步上限 `1e-4 V`、差分步 `1e-6 V`、
阻尼序列 `1/0.5/0.25/0.125` 均不变。

最初尝试“每轮预测扩展”，在已知 10% 失败点上得到
`0.00362104 → 0.00181052 → 0.00135789 → 0.00110547`，三轮耗尽，仍被拒绝。
首轮自动选出原先人工建议的六行，但后两轮各扩展到八行，选中阻尼降为 0.25。
该失败用时 **356.1 s**，保留在
[calibration](../../build/s03predict/calibration/)。不能把扩大范围等同于改善收敛。

根据这次校准及上一批首轮六行方案的成功结果，冻结为上述“只在首轮扩展”规则，
随后才开始新点验证；新点过程中没有调参。新增 `predict_boundary_cycles=1`
写入 policy 和身份记录，诊断接口可显式配置其他轮数，但 CLI 默认只用首轮。

## 算例和原资格边界

起点为上一批 8 行恢复方案的合格态：物理内压 `38.50511773208874 V`、
实际外压 `678.9130186976357 V`、漏电流 `6.404079009655471e-10 A/µm`。
导入前复验其完整器件证明与负载线绑定，不计为新增点。

沿用 SLOT 网格 13,881 节点、27,275 三角形，Si/PolySilicon、300 K，
原 IALMob、雪崩及输运几何配置；电子与空穴各 12,634 条有效行。
外电阻为 `1e12 Ω·µm`，参考原点 36 V，表中电压均已加参考原点。
求解器为 UCRT64 Release `build/s02merit/runner.exe`，HDF5 状态格式、已链接
UMFPACK，SHA-256 为
`20f5e126f06311ba1b7dbbdb0f83b21fba7c9f3d47d0b477ede3d81e5d86bbf3`。
本批没有重新编译 C++，局部差分小矩阵使用 NumPy。

原门槛保持：`abstol=1e-9`、`reltol=1e-8`、`eps_row=0.001`、
`scale_floor=1e-30`、全局闭合比 0.01、负载线残差 `1e-6 V`。
使用原显式块残差尺度；没有删除弱行、改变 scale floor 或提高容差。

新点继续沿用“耦合诊断初值 → poly 处理 → Poisson → 载流子修正 → Poisson”
路径，随后进入新的有界局部修正及原严格验收。
提议增长 20%，失败可回退 10%/5%；接受电流增长守卫 25%，内压增加/试探上限
0.1/0.05 V、允许下降最多 20 µV、停滞保护与原候选电流质量 0.5% 上限不变。
最多三个连续点，总求解路径预算 1800 s，单次子进程上限 120 s，
每个局部修正调用上限 450 s。

## 交接错误和成本口径

第一次入口复验使用了历史 24 次迭代配置，而父态证明绑定的是原严格路径的
40 次迭代配置，身份核对失败，未启动求解。改用父态绑定的完整 base 后进入新目录。

首个新点随后已完成原严格资格，但每点初值/偏压参与完整 base 哈希，直接把该
证明交给另一 base 的验证器仍触发身份不匹配。没有跳过检查，也没有修改旧证明：
最终入口使用已有 `adopt_validation(..., proof_directory=...)` 接口，重新检查
严格配置、物理/资格合同、状态、有效行及文件绑定，把已完成的验证绑定到本批
统一身份，再做实际外压确认。首点的求解与局部行审计没有重跑。

后续两点也通过相同复用接口绑定。旧入口及错误记录分别保留在
[s03adjacent](../../build/s03adjacent/) 和 [s03adjacent_v2](../../build/s03adjacent_v2/)，
最终试验在 [s03adjacent_final](../../build/s03adjacent_final/)。
旧错误摘要即使出现 `completed=true`，也不能代表已接受或达到目标。

首次已执行求解的入口墙钟 **273.0 s**，最终入口（含首点复用和确认）**650.2 s**，
合计执行墙钟 **923.1 s**，在 1800 s 路径预算内。上面的局部修正时间仅是其中一部分；
另有校准失败 356.1 s，不计入这条新点路径，也没有从总工作成本中隐去。
没有同一批新点的“关闭预测”配对对照或重复计时，因此不据此宣称提速倍数。

## 验证和限制

- 新增四项预测规则回归，覆盖干净但受影响的邻行、非固定节点号、差分列复用、
  同载流子邻域、原全局守卫和首轮限制。原默认关闭与全部行/预算保护测试保留。
- `ctest --preset windows-ucrt64-debug -R '^slot_ldmos_loadline_continuation$'`
  实际选中一个 CTest，内部 **162 项 Python 回归全部通过**。没有将其称为全仓测试。
- [独立证据审计](../../build/s03adjacent_final/audit.json) 通过：重新验证三个器件证明、
  实际外压确认、各次选中试探的全局条件、行比下降、全部超标行纳入、
  有效行集合不变、25% 增长守卫及原资料/冻结源码哈希。
  这是证据复核，不是从不同初值重求同一物理解。
- 旧生产 summary、audit、s30 账本及已有父态均未修改。既有 h5py/HDF5 小版本
  警告仍存在，本批状态读取与绑定审计通过，未升级依赖。

结果支持“仅首轮预测扩展”在这三个相邻点上可用，尚不足以证明所有偏压点均可恢复。
尤其首点最终行比已达门槛的 98.16%，不能假设后续没有新的困难行。
下一批适合保持该规则冻结，补同初值开关对照和少量独立复现，再继续有界推进；
不采用每轮持续扩大范围、不放宽门槛、不直接恢复无界扫描。

复现代码为 [局部修正模块](../../scripts/slot_local_row_repair.py)、
[冻结试验入口](../../build/s03adjacent_final/run.py)，测试见
[test_slot_local_row_repair.py](../../tests/regression/test_slot_local_row_repair.py)。
