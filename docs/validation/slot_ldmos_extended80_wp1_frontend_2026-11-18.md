# sd-sim WP1 精度分派与输入检查

此记录对应 [开发计划](../superpowers/plans/2026-11-18-sd-sim-extendedprecision80-development-plan.md) 的 WP1。WP0 使用 [SLOT binary64 基线](slot_ldmos_extended80_wp0_boundary_register_2026-11-18.md)。

当前普通 `sd-sim --check` 已通过原生 SLOT 的 IALMob 绑定与阶段生成。
严格 80 位求解仍返回 E202，runner 的能力报告为 `mixed`。下文按批次
保留早期仅能显式预检、普通入口报 E106 时的结果。

## SLOT 阶段绑定与装配输入补验

### 外电阻低位进入耦合负载线

在配置保留 `decimal_stage_controls.sweep.resistance_ohm_um` 时，
电势＋浓度耦合路径把十进制来源校验后按 80 位传给生产负载线。物理残差
先计算 \(C V_{\rm dev}+RI-V_{\rm out}\)，再转换到现有残差类型。直接
增广的电路行与原坐标线性质量检查也使用该电阻计算乘积及电压导数。
端口电流、器件及供电电压、矩阵存储和状态写回仍使用现有类型。
此改动覆盖耦合路径，外层标量电路与续算预测仍使用兼容值。

VM 上用真实 CMD 阶段生成对照 \(R=1\) 与 \(R=1+2^{-60}\)
\(\Omega\cdot\mu\mathrm{m}\)。两者的 binary64 配置值相同，生产负载线
在固定 `I=1`、`Vdev=0`、`Vout=1` 的合成对照中分别给出 0 和
\(2^{-60}\) V。原生 SLOT 的 \(10^{12}\ \Omega\cdot\mu\mathrm{m}\)
耦合阶段通过只读预检。Windows 的负载线回归 49 项及扫描合同回归 4 项通过。
VM 另用同一电阻输入构造抵消后的电路对角项，直接增广 Newton 一步到达
器件电压 0.25 V，负载线残差为 0。两项为合成算例的算术验收。

### IALMob/HFS 系数与 PolySi 参考势

原生 SLOT 宽精度阶段保留 172 个 IALMob/HFS 参数字面量，覆盖两种载流子的
三个晶向族和四个高场参数。C++ 在构建迁移率配置时逐项校验其 binary64
兼容值。在 300 K SLOT 元素路径中，饱和速度和指数按宽标量参加 HFS 值及
偏导计算。低场模型、屏蔽缓存、单元主状态及 HFS 输出仍使用原类型。
普通 binary64 阶段沿用已有参数和计算入口。

VM 普通 `sd-sim --check-arithmetic-input` 的两个原生阶段各核对了全部
172 个字面量。用实际生产迁移率读卡编译的 VM 对照在 SI 下读回电子和空穴
饱和速度 107,000 及 83,700 m/s，区分 binary64 兼容值相同而 80 位相差
\(2^{-60}\) 的 HFS 指数，并验证了单元求值和不匹配输入的拒绝行为。
80 位构建的 IALMob 雅可比回归通过 5 个用例和 2,438 个断言，
覆盖带当前高场计算的九列中心差分。

用已记录的原生公共能量参考 \(C_{\rm Si}=4.633703995135664\) eV、
原生热电压及 PolySi PAR 带隙和 DOS 系数，离线计算
`C_Si - chi(T) - Eg_eff(T)/2 - Vt*log(Nc/Nv)/2`。
`Eg_eff` 含 OldSlotboom 常数偏移，`chi(T)` 含温度修正。
结果约 0.007927767678211065 V，与生产绑定值相差
\(-2.73\times10^{-16}\) V。将用户硅 PAR 直接代入绝对参考势公式
得到 4.656444379751049 eV。原生如何由输入选择公共参考的过程仍待独立确认，
目前继续用已验证的绑定值。此项复算未执行新的器件求解。

阶段运行清单现在逐阶段记录仍使用 binary64 的输入消费方。即便 runner
通过格式握手，只有已验证完整覆盖的输入才能通过前端能力检查。
VM 普通精度 CMD 通过预检，严格 80 位分派仍在求解前返回 E202，
接受点数为零。

### 掺杂自动判定与低位核查

`sd-sim` 的 HDF5 TDR 和 GRD/DAT 导入使用同一套按区域判定。按实际
`datexcodes.txt` 识别施主、受主和活性字段，同一活性字段的化学名称别名
只计一次。处理独立物种、净加总掺杂和仅净掺杂三条路径。CMD 的
`ComputeDopingConcentration` 传到导入器。发生字段冲突时，预检给出区域、
节点及字段。SLOT 继续绑定原有网格、掺杂和状态，但需核对自动结果与绑定的
节点掺杂值。

用 VM 安装的 Sentaurus U-2022.12 字段定义做真实 CLI 预检和 C++ 审计。
原生 SLOT 的硅和多晶硅区域均选择净掺杂拆分，13,881 个节点逐项匹配已绑定表，
最大相对差为 0。独立 GRD/DAT 用例选择实际施主、受主物种，在四节点保留
\(8\times10^{15}\) 和 \(3\times10^{15}\ \mathrm{cm}^{-3}\) 两种分量。
净加总掺杂重建由本地回归核对。

独立低位用例从 DF-ISE 物种字段到实际生成的 `doping.csv` 保留了
\(2^{-60}\ \mathrm{cm}^{-3}\) 的施主差，在 binary64 下两值相等。
C++ 输入审计读出 `0x8p-3` 和 `0x8.000000000000008p-3`。VM 校验
退出码均为 0，未执行器件求解。

### 原生 SLOT 绑定输入审计

普通 `sd-sim device.cmd --check-arithmetic-input` 可审计带
`slot_ialmob` 侧车的原生输入。报告分别列出 TDR 导入器的 binary64
回环数据和准备交给 Vela 的网格、掺杂、材料与各阶段的十进制控制。
绑定网格、掺杂和参考配置以哈希核对。材料派生核查以实际生成的材料卡
为准，使用绑定配置的物理常数。

VM 的原生 SLOT 预检和 C++ 输入审计正常完成，核对了 22 个 CMD 词元、
3,319 个 PAR 数值及两个阶段各 15 个控制量。原生 TDR 与 Vela 绑定网格的
27,762 个坐标分量在 binary64 下全部一致。两份掺杂的 27,762 个分量中
有 25,520 个不同。Vela 绑定表按净掺杂拆分，TDR 导入数据有 12,760 个
节点的施主和受主同时非零。按
\(\lvert\Delta(N_D-N_A)\rvert/\max(\lvert N_{\rm net,Vela}\rvert,
\lvert N_{\rm net,TDR}\rvert,1\ \mathrm{cm}^{-3})\) 比较，只有一个节点
超过 \(10^{-12}\)，最大为 \(2.06\times10^{-11}\)。原始 TDR 数据和
实际绑定掺杂分开记录，实际算例继续使用哈希绑定的净掺杂表。

本次材料派生核查覆盖 Si。审计未调用器件求解阶段，未发布接受点。
生产状态和模型消费端的端到端 80 位验收仍需单独完成。

### CMD 输出检查点与扫压阶段生成

电压阶段的 `Plot(Time=...)` 与 `CurrentPlot(Time=...)` 采用原始十进制
数值排序、去重、展开区间并换算至偏压。带 `ExtendedPrecision` 的阶段
在 `decimal_stage_controls.sweep` 中保留显式偏压点和输出检查点。
`DCSweep` 读卡时校验各十进制值与对应的兼容字段。当前运行时落点列表
仍使用 binary64。旧输入没有这些数组时继续按原配置读取。

VM 实际 `sd-sim --check` 的 0–2 V 四节点对照中，三个输出检查点的相邻
间距均为 \(2^{-60}\) V。默认精度仅生成一个 1 V 检查点。C++ 使用生产
读卡的十进制解析函数重新读出两段间距，并验证错配的兼容值会被拒绝。
同份前端归档通过原生 SLOT CMD 的两个阶段预检。

### CMD 温度和生产尺度

扩展精度阶段保存 CMD 温度的原始十进制数值。Newton、Gummel 和
DC 扫描从同一个输入计算热电压，`UnitScalingSystem` 在目标精度下从该值
计算 \(V_0\)、扩散率、电场、电流和源项的尺度，再投影到现有尺度字段。
默认路径沿用 binary64 运算。两条路径都检查生产热电压与归一化电势尺度一致。

VM 的普通 `sd-sim --check` 对照使用 299.999999999999972 K 和
300.000000000000028 K。两臂的兼容温度均为 300 K，binary64 的尺度相同。
扩展精度 C++ 读卡得到的 \(V_0\) 分别为 `0x1.a78f208d2d752p-6` 和
`0x1.a78f208d2d753p-6` V，\(D_0\) 也相差 1 ULP。
另外核对了接近 binary64 舍入中点的温度，求解配置保留原数值及其兼容值，
以便核对重绑定时的温度身份。

### 原生 PolySi 默认材料

用户 PAR 的活跃带隙和 DOS 参数块仅覆盖 Silicon 与 Oxide。VM 使用
`sdevice -P` 导出原生 PolySi 默认参数，提取 Bandgap、eDOSMass 和
hDOSMass 后，由 `poly_material_parameters` 显式绑定。PolySi 的绑定卡使用
折入 OldSlotboom 常数偏移的带隙，以及经温度修正的电子亲和势。用该口径
投影到 binary64 后，本征浓度和空穴 DOS 分别差 1 和 3 ULP，另外三项一致。

普通 `sd-sim --check` 生成了含原始 PolySi 派生输入的材料卡。VM 的
C++ 生产材料读卡以 80 位重算后，带隙、亲和势、电子 DOS 和空穴 DOS
投影到现有字段与绑定值一致。本征浓度由
`14638805412.55916` 变为 `14638805412.559216` cm⁻³，相对差约
\(3.8\times10^{-15}\)。前端的 4 ULP 检查用于验证公式和绑定输入的
binary64 对照。参考势沿用绑定值，原生参考势的派生过程仍未复现。
同一生产读卡对照也通过了一个接近 binary64 舍入中点的温度样本。

### 阶段控制、坐标和原生硅材料

- 普通 `sd-sim` 在 VM 对照了两个相差 \(2^{-60}\) V 的原始 CMD 目标。
  宽精度阶段保留了电压跨度和 \(2^{-62}\) V 的首步，binary64 转换将此
  对照折为等压工作点。C++ 读卡同时核对了外电阻低位和 DF-ISE 坐标。
- 原生 SLOT 的 Si 材料与原生 PAR 在五个材料量的 binary64 投影上逐项相等，
  生产材料读卡由此接入带隙、电子亲和势、两种态密度和本征浓度的宽精度
  派生数据。多晶硅的默认参数接入见上一节。原生 TDR 坐标保持已核验的
  float64 来源。
- 本批验证数值到达阶段生成、接触、网格和材料读卡。进入当前求解状态
  时仍有 binary64 转换。原生完整求解返回 E202，runner 自报 `mixed`。

- VM 上普通 `sd-sim --check` 的 DF-ISE 开关对照均生成两个阶段。
  开启时，生产 CSV 保留相差 \(2^{-60}\) 的施主和受主两值，各阶段均选用
  十进制掺杂读取。关闭时，两值均为 1.0。原生 SLOT TDR 的专用绑定复验通过。
- 本次验证覆盖通用材料发射与生产读卡、DF-ISE 掺杂发射与阶段绑定。
  原生 SLOT 的专用材料卡、网格坐标、接触、偏压和端到端 80 位求解仍待验收。

## CLI 合同

- 省略精度开关或使用 `-ExtendedPrecision` 时，`sd-sim` 选择默认 runner。脚本显式启用 `ExtendedPrecision` 或 `ExtendedPrecision(80)` 时，各阶段生成的求解配置都要求端到端 80 位。
- 前端在启动求解前查询 runner 的 `--arithmetic-capabilities`。检查二进制基数、64 位有效尾数、最大指数 16384、端到端覆盖及显式后端覆写。探测结果及阶段请求保存在 `run_manifest.json`。能力查询失败及覆盖不足通过 E202 报告。
- 当前 `extended80` 构建报告 `mixed`，直接执行端到端 JSON 和通过 `sd-sim` 执行均会在写入接受态前退出。显式 native JSON 仍可通过 `solver.arithmetic_precision` 请求既有混合精度实验。
- 即使替换 runner 声明端到端支持，当前前端仍会明确报告 binary64 输入转换并拒绝启动。
- `--check` 可生成各阶段的配置，能力检查标为 `not_evaluated`。不支持的位宽和冲突开关在脚本解析阶段报告。

## 权威输入的精度核查

以 `1` 和精确十进制 `1.000000000000000000867361737988403547205962240695953369140625` 构造相差 \(2^{-60}\) 的样本。现有 CMD 解析将两种接触电压都写为 `1.0`，PAR 标量分类的数值也都为 `1.0`。侧车的标准 JSON 解码将第二种写法解析为同一个数值。边界集中在以下入口。

| 输入 | 已核对的舍入位置 | 后续需要的消费接口 |
|---|---|---|
| CMD | [parse_number](../../scripts/vela_sdevice/cmd_parser/syntax.py) 把原始 token 转为 Python `float`。 [阶段生成](../../scripts/vela_sdevice/deck_emit/__init__.py) 还会换算偏压、时间和电流目标。 | 保留权威有量纲字段的词面，按目标标量解析并生成偏压与目标。测试包括保存、加载和阶段重绑定。 |
| PAR | [参数 IR](../../scripts/sentaurus_parameter_ir.py) 数值分类使用 `float`。 [材料转换](../../scripts/vela_sdevice/materials/__init__.py) 会用派生计算结果生成材料 JSON。 | 在材料参数、DOS、带边和参考势生成前绑定目标标量与物理常数。 |
| 侧车与原生 JSON | [前端](../../scripts/vela_sdevice/orchestrator/__init__.py) 用标准 JSON 解码侧车，C++ 使用默认 `nlohmann::json` 读取配置。 | 在合并或读取配置时对参与求解的实数保留字面量，并验证最终消费者取得的值。 |
| 网格、掺杂和派生尺度 | [网格导入](../../scripts/vela_sdevice/mesh_import/__init__.py) 在 Python `float` 中处理 DF-ISE 与 TDR 导出数据， [网格读取](../../src/io/MeshReader.cpp) 和 [尺度构造](../../src/core/UnitScalingSystem.cpp) 使用当前 `Real`。 [常数](../../include/vela/core/PhysicalConstants.h) 为 `double`。 | 按来源记录原始精度，文本坐标和浓度以目标标量消费，已量化输入显式升精度，尺度计算使用相同标量。 |

独立 C++ 对照直接用两种 `ArithmeticReal` 读取该文本。binary64 的差值为零，extended80 的差值为 `0x8p-63`（即 \(2^{-60}\)）。生产路径的权威文本解析、派生计算与正向分派仍需实现并验证。

## 本地回归

CMD 解析、阶段生成和 orchestrator 回归共运行 100 项，92 项通过，8 项因缺少对应构建或外部输入而跳过。runner 错配和后端拒绝的针对性用例在最终前端修改后再次通过。

## Vela VM 验证

复用 VM 上同一基线的两套核心库，在独立目录重新编译两个 runner 的入口。按 `--arithmetic-capabilities` 复核，普通构建报告基数 2、53 位有效尾数、最大指数 1024。扩展构建报告基数 2、64 位有效尾数、最大指数 16384，覆盖为 `mixed`。

最终前端归档使用真实 `sd-sim` 启动器复验。省略开关和显式关闭均接受一个零偏压点。80 位检查模式生成各阶段计划并正常退出。缺失、错配、混合精度 runner 和 PARDISO 覆写均产生 E202。不支持的位宽和开关冲突产生 E104。另用能力握手替身声明端到端支持，确认前端仍在求解前拒绝 binary64 入参转换。直接运行要求端到端的原生 JSON 也在 runner 入口退出。预期拒绝的用例均未发布接受点。

VM 编译对照与最终 CLI 批次退出码均为 0。上述结果覆盖 WP1 的分派与能力检查。权威输入保真和端到端正向用例仍待验收。

## 权威输入检查入口

`sd-sim device.cmd --check-arithmetic-input` 读取配置正常通过检查且启用
`ExtendedPrecision` 的 DF-ISE 算例。前端同时提交 CMD 数值词元、PAR
有效定义中的数值词元、侧车 JSON 数字、GRD 顶点坐标和 DAT 掺杂数据。
侧车的字符串字段与数字字段分别处理。报告记录输入哈希、词面和 C++ 按编译
标量解析得到的十六进制值。独立 C++ 入口可对同一输入文件作 binary64
对照。热电压使用绑定的常数配置，另记录坐标到米和浓度到 m⁻³ 的换算。

本入口可证明所采数值在进入 C++ 时的精度。它不构造求解态，保真数据
尚未进入生产材料、接触、网格和时间步的消费者。活跃材料合并后的 DOS
与参考势、二进制 TDR 导入、阶段重绑定和严格 80 位正向求解还待验证。

VM 使用四节点 DF-ISE 配对，从真实 `sd-sim` 启动扩展 runner 的输入检查，
并将同一输入文件交给普通 runner 做对照。CMD 接触电压、PAR 的 `Bandgap.Chi0`、
侧车的 `psi_residual_ceiling`、GRD 的 x 坐标和 DAT 的 `DopingConcentration`
均取得相同结论。扩展构建把两个值分别读为 `0x8p-3` 和
`0x8.000000000000008p-3`，精确相差 \(2^{-60}\)。普通构建中两者相同。
